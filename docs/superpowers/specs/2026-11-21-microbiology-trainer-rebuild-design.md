# Переписывание Microbiology Trainer с нуля

Дата: 2026-11-21  
Ветка: `rebuild-from-scratch`

## 1. Контекст

Сейчас репозиторий содержит автономный одностраничный тренажёр по общей медицинской микробиологии. Фактическая версия в `index.html` — v2.5.2: разметка, стили, изображения, учебные данные и логика находятся в одном файле. README описывает v2.6, но `microbiology_trainer_v2_6.html` содержит только `PLACEHOLDER3`; эта несогласованность не является основанием добавлять отсутствующие функции.

В действующем `index.html` подтверждены:

- 10 заполненных подмодулей;
- 77 карточек теории;
- 228 тестовых вопросов;
- 6 заблокированных разделов;
- 9 микропрепаратов с 24 заданиями;
- 7 заданий на комплексное описание;
- подсказки, объяснения, повторение ошибок, результаты по темам;
- локальное сохранение прогресса и незавершённых занятий.

## 2. Цель

Сохранить текущий пользовательский сценарий и весь подтверждённый учебный контент, но заново создать интерфейс, компонентную архитектуру и реализацию на React + TypeScript + Vite.

Основной путь остаётся неизменным:

**Главная со списком модулей → теория → тест → результат.**

Практикум по микропрепаратам, комплексные описания, повторение ошибок и статистика остаются доступными как самостоятельные разделы.

## 3. Границы работ

### Входит

- Полностью новый визуальный дизайн и адаптивная раскладка.
- Разделение компонентов, состояния, учебных данных и ресурсов.
- Перенос всего содержимого без сокращения вопросов и занятий.
- Сохранение существующих учебных механик.
- Миграция известных данных прогресса из текущей версии.
- Автоматические тесты и проверка основных сценариев.
- Локальный preview и production-сборка.
- Подготовка к статической публикации без фактической публикации.

### Не входит

- Ежедневные планы, персональные тренировки, адаптивные алгоритмы и карта знаний.
- Новые учебные модули или переписывание учебных материалов.
- Регистрация, сервер, облачная синхронизация и аналитика пользователя.
- Экспорт/импорт, ситуационные задачи и другие функции из описания v2.6, отсутствующие в действующем `index.html`.
- Публикация на GitHub Pages, push и удаление существующих версий.

## 4. Пользовательский опыт

### Навигация

- **Компьютер:** верхняя панель с названием курса и общими действиями; слева навигация по разделам «Курс», «Практикум», «Мои ошибки» и «Прогресс»; справа основная рабочая область.
- **Телефон:** одноколоночная раскладка с компактной навигацией; основные действия остаются доступными без горизонтальной прокрутки.
- **Главная:** как и сейчас, содержит сгруппированный список модулей и подмодулей, состояние прохождения и вход в практикум. Персональный план и рекомендации не добавляются.
- **Теория:** последовательные занятия с кнопками «Назад» и «Дальше», индикатором положения и переходом к тесту после последнего занятия.
- **Тест:** один вопрос на экране, варианты ответов, подсказка при наличии, объяснение после ответа, повтор ошибок и итоговый результат.
- **Результат:** процент верных ответов с первой попытки, статистика по темам, разбор ошибок и переход к следующему подмодулю.
- **Практикум:** текущие режимы распознавания и комплексного описания с сохранением их правил подсчёта и повторения.

URL должны позволять обновить страницу и вернуться в текущий раздел. Используется hash-маршрутизация, чтобы прямые переходы работали на статическом хостинге без серверных rewrite-правил.

### Визуальное направление

Новый интерфейс в спокойном стиле учебного атласа:

- тёплый нейтральный фон и читаемые светлые поверхности;
- зелёный основной акцент, дополнительные цвета только для состояний и смысловых категорий;
- выразительный serif для заголовков и системный sans-serif для интерфейса и основного текста;
- новая сетка, отступы, иконография и компоненты; старый CSS не копируется;
- адаптивность от мобильной ширины до широкого рабочего стола.

## 5. Техническая архитектура

### Стек

- React;
- TypeScript в строгом режиме;
- Vite;
- React Router с hash-маршрутизацией;
- Vitest + React Testing Library для модульных и интеграционных тестов;
- Playwright для ключевых end-to-end сценариев.

Состояние реализуется через React Context и `useReducer`; отдельная библиотека управления состоянием не нужна.

### Структура

```text
src/
  app/                 # инициализация, маршруты, providers
  components/          # общие UI-компоненты
  features/
    course/            # каталог, теория, тест, результат
    microscopy/        # распознавание препаратов
    complex-cases/     # комплексные описания
    mistakes/          # повторение ошибок
    progress/          # статистика и отображение прогресса
  data/                # типизированные учебные материалы
  assets/              # изображения и самостоятельные SVG
  storage/             # версионированное сохранение и миграции
  styles/              # design tokens и глобальные стили
  test/                # общая конфигурация тестов
```

### Основные модели данных

- `Module` и `Submodule` — идентификатор, название, экзаменационные темы, состояние блокировки.
- `Lesson` — заголовок, типизированные блоки содержимого, иллюстрации.
- `QuizQuestion` — формулировка, варианты, индекс ответа, объяснение, подсказка и тема.
- `MicroCase` — изображение, источник/оговорка и связанные задания.
- `ComplexCase` — изображение, правильные значения полей и пояснения.
- `Progress` — завершённые попытки, ответы, точность, ошибки, результаты и незавершённое занятие.

Учебный контент отделяется от отображения. Существующие изображения извлекаются из data URL в отдельные ресурсы; подписи и предупреждения о неподтверждённых источниках сохраняются. Существующие учебные SVG переносятся как ресурсы или небольшие компоненты без смешения с логикой тестов.

## 6. Состояние и хранение

Новая версия использует версионированную схему `microbiology_trainer.progress.v3` в `localStorage`.

Миграция выполняется один раз при первом запуске новой версии и учитывает подтверждённые ключи:

- `micro_trainer_v24_state`;
- `micro_trainer_v24_stats`;
- `micro_wrong_v1`;
- `micro_complex_wrong_v1`.

Правила:

- идентификаторы модулей и заданий сопоставляются явно;
- неизвестные идентификаторы пропускаются без падения приложения;
- старые ключи не удаляются;
- повреждённые данные не применяются, пользователь получает ненавязчивое уведомление;
- при недоступном хранилище приложение работает в памяти и сообщает, что прогресс не сохранится;
- в процессе прохождения сохраняются раздел, подмодуль, занятие, порядок вопросов и текущий ответ;
- завершение попытки записывается один раз, повторный render не должен удваивать статистику.

## 7. Обработка ошибок

- Некорректный маршрут возвращает на главную или показывает понятный экран «Раздел не найден».
- Заблокированные и пустые модули нельзя случайно открыть.
- Пустой список ошибок показывает состояние с переходом к полному набору заданий.
- Отсутствующее изображение не ломает вопрос; отображается текстовое состояние ошибки.
- Ошибка хранилища не прерывает занятие.
- Error Boundary на уровне приложения предлагает вернуться на главную без потери старых данных.

## 8. Доступность

- Семантические кнопки, ссылки, заголовки, формы и подписи полей.
- Полная навигация основных сценариев с клавиатуры.
- Видимый focus, достаточный контраст и отсутствие передачи состояния только цветом.
- Осмысленные альтернативные тексты для учебных изображений.
- Уважение `prefers-reduced-motion`.
- Обновления результата ответа доступны screen reader через live region.

## 9. Тестирование и приёмка

### Автоматические проверки

- Подсчёт перенесённого контента: 10 активных подмодулей, 77 занятий, 228 вопросов, 9 микропрепаратов, 24 задания и 7 комплексных случаев.
- Переход по теории, старт теста, ответ, объяснение, переход к следующему вопросу.
- Подсчёт ответов с первой попытки и повтор ошибок.
- Комплексное описание и его повторение.
- Сохранение и восстановление незавершённого занятия после перезагрузки.
- Миграция известных старых ключей и обработка повреждённых данных.
- Блокировка пустых модулей и отсутствие дублирования завершённых попыток.

### Ручная проверка

- Полный путь хотя бы одного подмодуля.
- Полный практикум и комплексный случай.
- Повторение ошибок.
- Desktop и mobile viewport.
- Клавиатурная навигация.
- Production-сборка и отсутствие ошибок в консоли.

### Критерий готовности

Новая версия проходит перечисленные проверки, содержит весь подтверждённый контент, сохраняет текущие сценарии и не изменяет `main`. Публикация и удаление старых файлов не выполняются.
